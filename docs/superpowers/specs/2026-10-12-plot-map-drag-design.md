# 区画図のマスを動かす・保存する 設計

日付: 2026-10-12
対象: 区画管理の「地図を見る」（`PlotSectionMap`）
関係するリポジトリ: `komine-crm-frontend`（画面）、`komine-crm-backend`（保存）

## 目的

Excel の区画図のように、区画図の上でマスを自由に置き直せるようにする。置き直した場所は「修正を保存」で全員の区画図に反映する。

## 画面の動き

### 見る位置を動かす

- 区画図の空白部分をつかんで動かすと、見えている範囲だけがずれる（スクロールと同じ）。
- 区画の番号の場所は変わらない。保存もされない。

### 区画のマスを動かす

- 番号のマスをつかんで、区画図の中の空白マスに置くと、その番号だけが移る。
- すでに別の番号があるマスには置けない。置こうとすると元の場所に戻る。
- 区画図の外へは出せない。行や列は増やさない。
- 番号、空き・予約・契約・売却不可の色、契約者名はマスと一緒に動く。番号そのものは変わらない。
- 少しだけ動かして離したとき（4px 未満）は、今までどおりのクリック扱いにして、右の「選択中の区画」を表示する。
- 読み込み中・保存中は動かせない。

### ボタン

区画図の上部、「地図を閉じる」の横に置く。

| ボタン | 押すと |
| --- | --- |
| 修正を保存 | 今の並びを全員の区画図に反映する。動かしていないときは押せない。 |
| 元の並びに戻す | 自分の画面だけ Excel の最初の並びに戻す。全員の区画図は、そのあと「修正を保存」を押すまで変わらない。 |

- 保存していない移動があるときは、「保存していない移動があります」と表示する。
- 保存に成功したら「保存しました」と表示する。
- 保存に失敗したら、画面の並びは消さずに「保存できませんでした。もう一度押してください」と表示する。

### 保存せずに閉じるとき

保存していない移動がある状態で「地図を閉じる」または別の区の「地図を見る」を押すと、「保存していない移動があります。閉じますか？」と確認する。閉じた場合、全員の区画図は動かす前のままになる。

### 使える人

区画図を開ける人（viewer / operator / manager / admin）は、全員が移動と保存をできる。

## 保存の考え方

- Excel から作った最初の並び（`generated-layouts.ts`）は書き換えない。これを「元の並び」とする。
- 保存するのは、その区で元の並びから場所が変わったマスだけ。マスごとに「元の並びでの行・列」と「新しい行・列」を記録する。
  - 同じ区画図に同じ番号が何か所もある区がある（43 枚中 14 枚）ため、番号ではなく元の行・列を目印にする。
  - 確認用に番号も一緒に記録する。元の行・列にあるマスの番号が記録と違うとき（Excel の区画図を作り直したときなど）は、その記録を使わない。
- 区画図を開くときは、元の並びを出してから、保存済みの場所を上に重ねる。
- 保存は区ごとにまるごと置き換える。その区の古い記録を消して、今の画面の移動を書く。
  - 二人がほぼ同時に保存したときは、後から保存した人の並びになる。
  - 「元の並びに戻す」のあと保存すると、移動が一つもないので、その区の記録は空になる。
- 保存済みの場所が、区画図の外にある場合や、動いていない別のマス・他の移動先と重なる場合は、そのマスの保存済みの場所を使わず、元の場所に出す。

## データ

backend に新しいテーブルを足す。

```
plot_map_cell_positions
  id          uuid, 主キー
  map_id      varchar(50)  区画図 ID（例: "1-A"）
  origin_row  integer      元の並びでの行（0 始まり）
  origin_col  integer      元の並びでの列（0 始まり）
  plot_label  varchar(50)  確認用の番号（例: "12"）
  row         integer      新しい行（0 始まり）
  col         integer      新しい列（0 始まり）
  updated_by  integer      保存したスタッフ（staff.staff_id）。外部キーは張らない
  updated_at  timestamp
  一意: (map_id, origin_row, origin_col)
  一意: (map_id, row, col)
```

## API

### 取得（既存を拡張）

`GET /plots/inventory/map?mapId=1-A`

返す値に `positions` を足す。

```json
{
  "mapId": "1-A",
  "plots": [],
  "positions": [{ "originRow": 1, "originCol": 4, "plotLabel": "12", "row": 3, "col": 5 }]
}
```

### 保存（新規）

`PUT /plots/inventory/map/positions`

```json
{
  "mapId": "1-A",
  "positions": [{ "originRow": 1, "originCol": 4, "plotLabel": "12", "row": 3, "col": 5 }]
}
```

- 権限: viewer / operator / manager / admin。
- 入力チェック: `mapId` が既知の区画図 ID であること、行・列が 0 以上の整数であること、同じ元のマスや同じ移動先が重複していないこと。
- 一つのトランザクションで、その `mapId` の記録を全部消してから書き直す。
- 成功したら、保存後の `positions` を返す。
- 区画図の大きさや、番号が区画図にあるかどうかの確認は、区画図データを持つ画面側で行う。

## 画面側の作り

- `lib/plot-maps/positions.ts`（新規）: 元の並びに保存済みの場所を重ねる関数、空白マスに置けるかを調べる関数、今の並びと元の並びの差分を出す関数。どれも画面の部品を使わない純粋な関数にする。
- `lib/api/plot-map.ts`: `positions` の受け取りと、保存用の `savePlotMapPositions` を足す。モックデータのときは画面の中だけで保存したことにする。
- `hooks/usePlotMap.ts`: `positions` を返す。保存関数と保存中の状態を持つ。
- `components/plot-map/PlotSectionMap.tsx`: 画面上の並び（下書き）を持つ。マスのドラッグ、空白のドラッグによるスクロール、2 つのボタン、未保存の表示を足す。マスの見た目は今の `MapCellButton` を使う。
- `components/plot-availability-management.tsx`: 閉じるときと別の区を開くときに、未保存の確認を入れる。

ドラッグはブラウザの Pointer Events で作り、新しい部品集は足さない。

## 今回やらないこと

- 行・列を増やす、区画図の外へ広げる
- 番号を書き換える、区画を増やす・消す
- 区画を入れ替える（空白マスにだけ置ける）
- 移動の履歴、一手ずつ戻す
- 同時編集の警告（後から保存した人の並びになる）
- キーボードでのマス移動

## 確認すること

| 確認 | 期待する結果 |
| --- | --- |
| 空白をつかんで動かす | 見える位置だけ動く。番号の場所は変わらない |
| 番号を空白マスへ置く | 自分の画面でだけ動く。「保存していない移動があります」と出る |
| 番号を別の番号のマスへ置く | 置けず、元の場所に戻る |
| 少しだけ動かして離す | 右に選択中の区画が出る |
| 保存せずに閉じる | 「保存していない移動があります。閉じますか？」と出る |
| 修正を保存 | 別の人の画面でも同じ場所になる |
| 元の並びに戻す → 修正を保存 | 全員の区画図が Excel の最初の並びに戻る |
| 保存に失敗する | 画面の並びは残り、もう一度押すよう表示される |

自動テストでは次を見る。

- frontend: `positions.ts` の重ね合わせ・置けるかの判定・差分（単体テスト）、`PlotSectionMap` のボタンと未保存表示（部品テスト）
- backend: 保存 API の入力チェック、区ごとの置き換え、取得時に `positions` が返ること
